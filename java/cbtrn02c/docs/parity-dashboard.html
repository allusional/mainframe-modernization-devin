How parity was proven

  1. Run the originalThe unchanged COBOL program was compiled and executed with GnuCOBOL over the sample card, account and transaction data.
  2. Capture the golden outputIts four output files, its messages and its return code were stored as the reference baseline.
  3. Run the rewriteThe Java program read the same input files with the run timestamp pinned to the same value, so the comparison is exact.
  4. Diff every fieldAn automated checker compares each record field by field and reports any difference by business field name. It runs on every build.

Business rules carried over

Validation

Unknown card (100), account not found (101), over credit limit (102) and transaction received after account expiry (103) — same codes, same wording on the reject file.

Posting

Account balance, cycle credit and cycle debit are updated exactly as before, and category balances are created on first use.

Money handling

All amounts use exact decimal arithmetic, matching the mainframe field definitions to the cent. No floating point anywhere in the rewrite.

Operations

The job still reports processed and rejected counts and still ends with return code 4 when rejects occur, so existing schedules and alerts keep working.

Findings raised for the business

Reproduced, not changed

Over-limit rejects can be re-labelled as expired

A transaction that is both over the credit limit and past the account expiry date is reported only as "after expiration". Reject statistics understate over-limit activity. The rewrite keeps this behaviour deliberately; changing it is a business decision.

Reproduced, not changed

New category balance records inherit stray bytes

When a category balance row is created, unused trailing bytes are copied from the previously read record instead of being cleared. Harmless today, but worth cleaning up if these records are ever exported downstream.

Dead code

One error path can never trigger

An account-update failure branch in the original program is unreachable, so it was documented rather than carried into the new code.

Test coverage gap

Sample data only exercises one reject reason

All 38 rejects in the sample data are over-limit. The other three reject reasons and the accept-on-equality boundaries are covered by dedicated automated tests instead of by the data comparison.
